## 1. What is Clustering and Why We Need It

Clustering is an **unsupervised machine learning technique** that groups similar data points together without needing any pre-existing labels. The algorithm finds structure in the data on its own.

In this project, clustering is applied to the **207 text chunks** produced by the data pipeline. Each chunk is represented as a **384-dimensional embedding vector** generated by `all-MiniLM-L6-v2`. Chunks that are semantically similar — that talk about the same banking topic — will have embedding vectors that point in similar directions in that 384-dimensional space. K-Means finds those natural groupings.

**The problem it solves:**

The RAG pipeline (v1) searches all 207 chunks every time a question is asked. While this works correctly, it is not efficient — a question about loan repayment has no reason to search through chunks about digital banking registration or remittance limits. By grouping chunks into topic clusters first, the v2 pipeline can narrow its search to only the relevant cluster, reducing the search space from 207 chunks to approximately 30-40 chunks per query.

## 2. Why Clustering Over Classification

The optional ML component for this project had three choices: Classification, Clustering, or Summarization. Clustering was selected over Classification for the following specific reasons.

### Classification Requires Labeled Data — We Have None

Classification is a **supervised learning** technique. To train a question classifier that routes questions to the correct document category, you need a labeled dataset: hundreds or thousands of example questions each tagged with the correct category label.

This project does not have that dataset. The source data consists of bank FAQ PDFs — raw documents with no question-label pairs attached. Creating a labeled dataset manually would require:

- Writing or collecting hundreds of example questions
- Assigning a category label to each one
- Verifying the labels are consistent and correct

This is significant manual effort before any ML work even begins. For a project of this scope, that cost is not justified.

### Clustering Requires No Labels at All

K-Means is **unsupervised** — it finds natural groupings in the data using only the embedding vectors, with zero manual annotation. The only manual step in the entire clustering pipeline is assigning short human-readable names to the clusters after they are found, which takes a few minutes by reading the TF-IDF top terms per cluster.

### The Dataset is Too Small for Classification

Classification models — even simple Logistic Regression — need enough examples per class to generalize. With 207 total chunks spread across 6 to 8 topic categories, each category would have approximately 25-35 examples. That is generally insufficient for training a reliable text classifier that will perform well on unseen questions at inference time.

Clustering works on exactly this dataset size. K-Means on 384-dimensional embeddings is stable and interpretable even with 200 data points.

### Speed — No Model Inference at Query Time

A trained classification model, even Logistic Regression, requires running a vectorizer and a model `predict()` call at query time for every incoming question. Clustering eliminates this: the cluster prediction in v2 is done by computing **K dot products** between the question vector and the K pre-computed cluster centroids. For K=6 this is 6 multiplications — essentially free computation.

### Clustering Output Directly Improves Retrieval

Clustering produces a `cluster_id` field on every chunk, which is exactly what the RAG v2 pipeline needs to scope its FAISS search. The output of clustering integrates directly into the retrieval system with no intermediate model inference step. Classification would require training and saving a separate model, loading it at runtime, and feeding it features — more moving parts, more potential failure points.

### Summary Comparison

| Criterion | Classification | Clustering |
|---|---|---|
| Labeled training data required | Yes — hundreds of examples | No |
| Works on 207 data points | Poorly | Well |
| Manual effort before training | High | Minimal |
| Query-time inference cost | Model predict() call | K dot products |
| Integration into RAG | Extra inference step | Direct — cluster_id on chunks |
| Reproducibility | Depends on data quality | Deterministic with fixed seed |

## 3. Why K-Means Over Other Algorithms

Several clustering algorithms exist. K-Means was chosen for this project over the alternatives for well-defined reasons.

### K-Means vs DBSCAN

DBSCAN (Density-Based Spatial Clustering of Applications with Noise) finds clusters of arbitrary shape and can identify outlier points that do not belong to any cluster. It does not require specifying K in advance.

**Why not DBSCAN here:**
- DBSCAN has two hyperparameters (`eps` and `min_samples`) that are sensitive and hard to tune on high-dimensional data. In 384 dimensions, the concept of "density" becomes unreliable because distances between all points become similar — this is the curse of dimensionality.
- DBSCAN on dense embedding spaces often produces either one large cluster or many tiny ones, depending on the `eps` value. Getting a clean 6-cluster result is not reliable.
- DBSCAN does not produce centroids. Without centroids, the cluster prediction step in RAG v2 — which works by finding the nearest centroid to the question vector — cannot be implemented simply.

### K-Means vs Hierarchical Clustering

Hierarchical clustering (Agglomerative) builds a tree of merges from the bottom up without needing K specified in advance. The dendrogram can be cut at any level to get the desired number of clusters.

**Why not Hierarchical here:**
- Hierarchical clustering has `O(n^2)` or `O(n^2 log n)` time and memory complexity. For 207 points it would work, but it does not scale if the chunk count grows.
- Like DBSCAN, it does not produce centroids in the same way K-Means does, making the RAG v2 centroid-prediction step harder to implement cleanly.
- K-Means with the Elbow Method gives equally good cluster quality for this data size with less complexity.

### K-Means vs Gaussian Mixture Models (GMM)

GMM is a probabilistic model that assigns soft cluster memberships — a chunk can partially belong to multiple clusters with different probabilities.

**Why not GMM here:**
- Soft assignments add complexity without benefit for this use case. The RAG v2 pipeline needs a hard assignment: one cluster per question. GMM would require picking the highest-probability cluster at prediction time anyway.
- GMM has more hyperparameters (covariance type) and is more sensitive to initialization.
- K-Means is faster and easier to understand, debug, and explain.

### Why K-Means is the Right Choice

- Produces **centroids** — directly usable for fast query-time cluster prediction in RAG v2
- Works well on **L2-normalized dense embeddings** — the geometry matches K-Means assumptions
- **Deterministic** with a fixed random seed — results are reproducible
- **Fast** — `O(n * K * iterations)` complexity, runs in seconds on 207 points
- **Interpretable** — inertia metric and elbow plot give clear guidance on K selection
- **Widely understood** — straightforward to document and explain

## 6. Embedding Normalization

Before clustering, all embeddings are L2-normalized to unit length using `sklearn.preprocessing.normalize`.

**Why this matters:**

K-Means minimizes Euclidean (L2) distance between points and their assigned centroids. The FAISS index in this project uses **inner product search** on L2-normalized vectors, which is mathematically equivalent to cosine similarity. If we cluster using raw embeddings with Euclidean distance but retrieve using cosine similarity, the two operations are measuring different things — clusters found by K-Means would not correspond cleanly to the retrieval neighborhoods used in FAISS.

By normalizing embeddings to unit length before K-Means, Euclidean distance between any two points becomes a monotone function of cosine distance between them. This makes the clustering geometry consistent with the retrieval geometry.

**Formula:**

```
For each embedding vector v:
    v_normalized = v / ||v||_2
    
Where ||v||_2 = sqrt(sum of squared components)

After normalization: ||v_normalized||_2 = 1
```

## 7. Elbow Method — Finding Optimal K

Before running the final K-Means, we need to determine how many clusters to use. K-Means requires K to be specified in advance. The Elbow Method is a standard technique for finding a good K.

**How it works:**

For each value of K from `K_MIN=3` to `K_MAX=12`, K-Means is run and the **inertia** is recorded. Inertia is the sum of squared distances from each point to its assigned cluster centroid:

```
Inertia = sum over all chunks i of: ||chunk_i - centroid(cluster(i))||^2
```

As K increases, inertia always decreases — with K equal to the number of data points, each point is its own cluster and inertia is zero. The question is how fast it decreases.

**The elbow:**

When plotted as a curve, inertia typically drops steeply for small K and then flattens out. The point where the curve transitions from steep to flat — the "elbow" — is where adding more clusters gives diminishing returns in terms of reducing inertia. This is the optimal K.

**Settings used:**

```python
K_MIN  = 3    # minimum K to test
K_MAX  = 12   # maximum K to test
n_init = 10   # independent runs per K — ensures the inertia recorded is the best of 10 attempts
```

**After inspection:**

`K_FINAL` is set in the config cell. If the elbow appears at K=5 or K=7 instead of the default K=6, update `K_FINAL` and re-run from Step 3 onward. The `CLUSTER_LABELS` dict in Step 4 must also be updated to have the correct number of entries.

## 8. K-Means Algorithm — How It Works

K-Means finds K cluster centers (centroids) such that the total squared distance from every point to its nearest centroid is minimized. It does this iteratively:

**Step 1 — Initialization:**
K initial centroid positions are chosen using the k-means++ method (explained in Section 9).

**Step 2 — Assignment:**
Every data point (chunk embedding) is assigned to the cluster whose centroid it is closest to, measured by Euclidean distance.

**Step 3 — Update:**
Each centroid is recomputed as the mean of all points currently assigned to its cluster.

**Step 4 — Repeat:**
Steps 2 and 3 repeat until either the assignments stop changing or `max_iter=300` is reached.

**Convergence:**

K-Means is guaranteed to converge — assignments can only stay the same or improve at each iteration. However, it may converge to a local minimum rather than the global minimum, which is why `n_init=10` runs the full algorithm 10 times and keeps the result with the lowest final inertia.

**Settings used in this project:**

```python
KMeans(
    n_clusters    = K_FINAL,    # number of clusters
    init          = "k-means++", # smart initialization
    n_init        = 10,          # 10 independent runs, best kept
    max_iter      = 300,         # max iterations per run
    random_state  = 42           # fixed seed for reproducibility
)
```

## 9. k-means++ Initialization

Standard K-Means initializes centroids by picking K random data points. This can lead to poor starting positions where two centroids start very close together, causing slow convergence and suboptimal clustering.

**k-means++ fixes this** by choosing initial centroids that are spread apart:

1. Pick the first centroid uniformly at random from all data points
2. For each remaining centroid, pick a new data point with probability proportional to its squared distance from the nearest already-chosen centroid — points far from existing centroids are more likely to be chosen
3. Repeat until K centroids are chosen

**Effect on this project:**

With 207 chunks in 384 dimensions, k-means++ consistently produces better clusters than random initialization and converges in fewer iterations. Combined with `n_init=10`, it ensures that the final clustering is stable and reproducible.

## 10. Cluster Label Assignment via TF-IDF

K-Means assigns integer IDs (0, 1, 2...) to clusters. These numbers have no meaning on their own. To understand what each cluster represents, we use TF-IDF to find the most distinctive terms in each cluster's text content.

**How TF-IDF labeling works:**

1. All chunk texts belonging to each cluster are joined into one large document
2. TF-IDF is computed across these K documents (one per cluster)
3. The top 10 terms by TF-IDF score are printed for each cluster
4. These terms are inspected manually to write a short descriptive label

**Why TF-IDF and not raw word frequency:**

Raw word frequency would surface common banking terms like "account", "bank", "customer", "please" across all clusters — terms that appear frequently everywhere and tell us nothing distinctive about a specific cluster.

TF-IDF (Term Frequency - Inverse Document Frequency) weights terms by how common they are within a cluster relative to how common they are across all clusters. A term that appears frequently in the "Remittance" cluster but rarely in other clusters gets a high TF-IDF score for that cluster — it is genuinely distinctive.

**Settings used:**

```python
TfidfVectorizer(
    max_features = 500,        # vocabulary capped at 500 terms
    stop_words   = "english",  # removes common English stop words
    ngram_range  = (1, 2)      # includes bigrams like "profit rate", "account opening"
)
```

Bigrams are included because many banking concepts are two-word phrases. A unigram analysis would miss "profit rate", "digital banking", "home remittance" as meaningful units.

**Cluster labels assigned (default, adjust after running):**

| Cluster ID | Label |
|---|---|
| 0 | Account Opening & Requirements |
| 1 | Loan & Financing Products |
| 2 | Digital Banking & Online Services |
| 3 | Remittance & International Transfers |
| 4 | Profit Rates & Investment Products |

These are starting labels. After running the notebook and seeing the actual TF-IDF terms for your data, update `CLUSTER_LABELS` in Step 4 accordingly.

## 11. t-SNE Visualization

t-SNE (t-distributed Stochastic Neighbor Embedding) is used to project the 384-dimensional embeddings down to 2 dimensions for visual inspection.

**Why t-SNE and not PCA:**

PCA (Principal Component Analysis) is a linear projection — it preserves global variance but often collapses local cluster structure in high-dimensional semantic embeddings. t-SNE is non-linear and specifically optimized to preserve **local neighborhood structure**, which means points that are close together in 384 dimensions will also be close together in the 2D plot. This makes t-SNE far more useful for visualizing whether clusters are genuinely separated.

**What to look for in the plot:**

- Well-separated colored groups indicate the clustering found genuinely distinct topic areas in the data
- Overlapping or touching groups indicate those topics are semantically close in the embedding space — for banking FAQs this is expected, since topics like "digital banking" and "account opening" have related vocabulary
- Isolated points far from their cluster center may indicate mis-clustering or a chunk that does not fit neatly into any topic

**Settings used:**

```python
TSNE(
    n_components  = 2,      # output dimensions
    perplexity    = 30,     # roughly the effective number of neighbors per point
    n_iter        = 1000,   # more iterations = more stable layout
    learning_rate = 200,    # standard default
    random_state  = 42,     # fixed seed for reproducibility
    init          = "pca"   # PCA initialization is more stable than random in high-dim
)
```

**Perplexity guidance:**

For a dataset of 207 points, `perplexity=30` is appropriate. The general rule is perplexity should be between 5 and 50, and roughly `sqrt(N)` is a starting point. For N=207 that is approximately 14, so 30 is on the higher end and will produce slightly more spread-out clusters.

**Runtime:**

t-SNE on 207 points takes approximately 30-60 seconds. It is only run once for visualization — it is not used at query time in the RAG pipeline.

## 14. Design Decisions Summary

| Decision | Choice | Reason |
|---|---|---|
| ML technique | Clustering (unsupervised) | No labeled data available; dataset too small for supervised learning |
| Algorithm | K-Means | Produces centroids; fast; works well on normalized dense embeddings |
| Initialization | k-means++ | Better starting positions; faster convergence; reduces local minima risk |
| K selection | Elbow Method | No labels needed; visual inspection is reliable for this data size |
| Distance metric | Euclidean on L2-normalized vectors | Equivalent to cosine distance; consistent with FAISS inner product search |
| Labeling method | TF-IDF top terms | Surfaces cluster-distinctive terms automatically; no manual annotation needed |
| Visualization | t-SNE | Preserves local cluster structure in 2D better than PCA for semantic embeddings |
| n_init | 10 | Multiple restarts reduce risk of poor local minima |
| Random state | 42 | Fixed seed ensures results are fully reproducible across runs |
